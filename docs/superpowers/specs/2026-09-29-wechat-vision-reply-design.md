# 微信数据库收消息与视觉发送设计

更新日期：2026-09-30

## 当前方案

用户确认：收消息依赖本机微信数据库密钥，视觉模型用于搜索定位和发送前标题确认。早期提出的视觉收消息、密钥失败后自动切换视觉监听方案已废弃，不应按旧方案继续实现。

流程：验证本机密钥 → 数据库监听新消息 → 规则或 AI 生成回复 → 重新搜索联系人 → 视觉确认唯一联系人行 → 确认聊天标题 → 发送 → 按数据库会话 ID 回读。

## 本机数据库适配

- 每台电脑独立发现微信数据目录、验证已有密钥；失效时重新提取，不能从其他电脑复制密钥。
- Windows 微信 4.1.15.13 使用只读 `Config.Cipher` 对象恢复路径，通过 SQLCipher 页面 HMAC 验证后缓存，保留旧版本扫描回退。
- 联系人库和消息库不可验证打开时，自动回复停发。
- Windows EXE 提示管理员权限；macOS 使用平台自己的密钥恢复路径，不能直接套用 Windows 对象布局。

## 发送与白名单

- Web 保存的私聊白名单用于授权会话；不限于某两个测试联系人。空名单停发，保存后重建监听。
- 数据库联系人优先使用本机备注作为搜索标题，昵称、备注与数据库会话 ID 分开处理。同名联系人必须拒绝发送。
- 每次发送重新搜索，禁止凭上一次聊天或 TTL 跳过目标检查。
- DeepSeek `deepseek-flash` 关闭思考、温度为 0，返回结构化 JSON。仅联系人行影响唯一性和结果完整性，下方群聊、收藏或网页结果截断不影响联系人检查。
- Windows 每次截图和鼠标操作前检查前台窗口，视觉返回后再次检查位置与前台归属。激活失败、焦点丢失或标题不符立即停止。
- Windows 自动回复携带明确的数据库会话 ID，发送后必须确认该会话中新产生的本人文本记录；不会因关闭可选校验配置而跳过这一步。未确认时不自动重发。
- Windows 自动回复及独立测试仅向视觉 API 提交搜索结果和聊天标题，不提交消息气泡用于发送确认。旧的无会话 ID 手动发送与 macOS 发送后视觉确认仍是兼容路径，不能把 Windows 已验证范围理解为这些路径都已验收。

## 配置与交付

API key 存在本机 `.env`；进程环境变量优先。数据库密钥、用户配置、聊天数据库、截图、日志、测试原始报告和带本地配置的 EXE 均不进入仓库或通用安装包。

## 验证结果与边界

2026-09-30 在 Windows 微信 4.1.15.13 实机验证了本机数据库密钥恢复、联系人与消息库打开、新消息读取及 AI 生成。独立发送测试对两个不同私聊交替三轮，六条消息全部按目标会话 ID 回读成功；原始记录只保存在本机 `data/`，公开文档不记录账号 ID 和聊天内容。

正式 Windows 发送流程已合入这条数据库确认路径。后端测试 166 项通过、4 项跳过，EXE 构建及导入检查通过。完整流水线的新消息触发、不同电脑和窗口布局仍以相应实机结果为准；macOS 仅完成代码与模拟测试，Mac 实机验收待有设备时补测。
